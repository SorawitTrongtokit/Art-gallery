# Inner Child

เว็บนิทรรศการศิลปะและหน้าแอดมินสำหรับจัดการผลงานด้วย Astro, TypeScript, Supabase และ Vercel ผู้ชมเห็นฉบับล่าสุดที่เผยแพร่เมื่อเปิดหน้าเว็บ

## รันในเครื่อง

ต้องมี Node.js 24, npm และ Docker ที่กำลังทำงาน

~~~sh
npm ci
npx supabase start -x realtime,imgproxy,edge-runtime,logflare,vector,supavisor
~~~

คัดลอกไฟล์ .env.example เป็น .env.local แล้วตั้งค่าจาก Supabase ในเครื่อง พอร์ต API ของโครงการนี้คือ 56321

| ตัวแปร | ค่า |
| --- | --- |
| SUPABASE_URL | http://127.0.0.1:56321 |
| SUPABASE_PUBLISHABLE_KEY | Publishable key หรือ anon key ของ Supabase ในเครื่อง |
| DEMO_SUPABASE_SECRET_KEY | Secret key หรือ service role key ในเครื่องสำหรับสคริปต์ seed |
| DEMO_ADMIN_EMAIL, DEMO_ADMIN_PASSWORD | อีเมลและรหัสผ่านสำหรับบัญชีทดสอบแอดมิน |
| DEMO_VIEWER_EMAIL, DEMO_VIEWER_PASSWORD | อีเมลและรหัสผ่านสำหรับบัญชีทดสอบที่ไม่มีสิทธิ์แอดมิน |

ดูค่าของระบบในเครื่องด้วย npx supabase status แล้วเก็บค่าไว้ใน .env.local ซึ่ง Git ข้ามไฟล์นี้ สคริปต์ seed สร้างบัญชีทดสอบและข้อมูลจำลอง 144 ชิ้นบน Supabase ในเครื่องที่พอร์ตของโครงการเท่านั้น เมื่อมีเนื้อหาอยู่แล้ว สคริปต์จะเก็บเนื้อหาเดิมไว้

~~~sh
npm run seed:demo
npm run dev
~~~

เปิด [เว็บในเครื่อง](http://127.0.0.1:4321) และ [หน้าแอดมิน](http://127.0.0.1:4321/admin) ใช้บัญชี DEMO_ADMIN ที่ตั้งไว้เพื่อทดสอบแอดมิน

## จัดการผลงาน

1. เข้า **ผลงาน → เพิ่มผลงาน** ระบุรหัส เช่น IC-001 เลือกหมวด กรอกชื่อ ผู้สร้าง และรายละเอียด แล้วเลือกไฟล์ JPG, PNG หรือ WebP หนึ่งรูป ขนาดไฟล์ต้นทางสูงสุด 30 MB
2. กด **บันทึกร่าง** แล้วเปิด **ดูตัวอย่างร่าง** เพื่อดูหน้าตาเว็บจริง ร่างของงานที่เผยแพร่แล้วจะแสดงในหน้าตัวอย่าง ผู้ชมจะเห็นฉบับล่าสุดที่เผยแพร่
3. กด **เผยแพร่ฉบับร่าง** หรือเลือกหลายรายการจากหน้า **ผลงาน** แล้วกด **เผยแพร่รายการที่เลือก** รายการที่เผยแพร่ต้องมีชื่อ ผู้สร้าง หมวด และรูปครบ
4. กด **เก็บเข้าคลัง** เมื่อต้องการนำผลงานออกจากแกลเลอรี กรองสถานะ **เก็บเข้าคลัง** เพื่อค้นหาและกู้คืนเป็นร่าง ส่วนเมนู **ประวัติ** ใช้คัดลอกฉบับก่อนหน้ามาเป็นร่างเพื่อแก้หรือเผยแพร่อีกครั้ง

แก้สไลด์ เรื่องราว ช่องทางติดต่อ และข้อมูลหมวดผ่านเมนู **เนื้อหาเว็บ** แล้วบันทึกร่าง ดูตัวอย่าง และเผยแพร่ตามลำดับ ใช้ลิงก์ HTTPS หรือ mailto สำหรับช่องทางติดต่อ

## นำเข้าผลงานเป็นชุด

1. ดาวน์โหลด [CSV ตัวอย่าง](examples/artworks-template.csv) หรือใช้ปุ่มดาวน์โหลดในหน้า **นำเข้า** เปิดใน Excel หรือ Google Sheets แล้วส่งออกเป็น CSV UTF-8
2. ใช้รหัสผลงานคงที่และรหัสหมวด 01–07 ระบุชื่อไฟล์ในคอลัมน์ image_file ให้ตรงกับรูปที่เลือกอัปโหลด ถ้ารายการเดิมจะใช้รูปเดิมให้เว้นช่องนี้ว่าง ข้อความที่มีเครื่องหมายจุลภาคหรือหลายบรรทัดให้ใส่ผ่านช่องของสเปรดชีตตามปกติ
3. เลือก CSV และรูป กด **ตรวจรายการนำเข้า** แก้รหัสซ้ำ หมวดผิด หรือไฟล์รูปที่ระบบหาไม่เจอ แล้วตรวจใหม่ กด **ยืนยันบันทึกเป็นร่าง** เมื่อตรวจครบ การนำเข้ารหัสเดิมจะอัปเดตฉบับร่างของงานเดิม
4. หากรูปบางไฟล์อัปโหลดไม่สำเร็จ ให้กดยืนยันอีกครั้งในหน้าเดิมเพื่อใช้ไฟล์ที่ส่งสำเร็จแล้ว เมื่อบันทึกสำเร็จ ตรวจงานในรายการฉบับร่างแล้วเผยแพร่ชุดที่พร้อม

ภาพฉากห้องใช้ images/background.jpg ส่วนตำแหน่งจุดกดใช้คลาส hs-1 ถึง hs-7 ใน css/main_menu.css เมื่อได้ภาพจริงจากฝ่ายศิลป์ ให้เทียบตำแหน่งบนเดสก์ท็อป แท็บเล็ต และมือถือ

## ตรวจสอบโครงการ

~~~sh
npm run check
npm test
npm run test:db
npm run test:e2e
npm run build
~~~

ชุดทดสอบฐานข้อมูลใช้ Supabase ในเครื่อง ชุดทดสอบเบราว์เซอร์ใช้บัญชีและข้อมูลจากสคริปต์ demo บน Windows จะใช้ Microsoft Edge ที่ติดตั้งอยู่ บนระบบอื่นให้ติดตั้ง Chromium ด้วย npx playwright install chromium

## เตรียมระบบจริงเมื่อได้รับอนุมัติ

1. สร้าง Supabase สำหรับ Inner Child ในสิงคโปร์ ใช้ migrations ใน repo และปิดการสมัครสมาชิกเองใน Supabase Auth สร้างบัญชีแอดมินผ่าน Dashboard แล้วเพิ่ม User ID ของบัญชีลงใน public.catalog_admins
2. ตั้ง Vercel เป็น Astro บน Node.js 24 และใช้ SUPABASE_URL กับ SUPABASE_PUBLISHABLE_KEY ของโครงการจริง ค่า DEMO_* ใช้สำหรับสภาพแวดล้อมทดสอบในเครื่อง
3. สร้าง production deployment แบบยังไม่ผูกโดเมน ใช้หน้าแอดมินนำเข้าข้อมูลจริงเป็นร่าง ตรวจสิทธิ์และภาพจากฝ่ายศิลป์บน URL ทดสอบ แล้วเผยแพร่ชุดที่อนุมัติก่อน promote deployment ไปยังโดเมนจริง
4. ตรวจหน้าแรก ห้อง แกลเลอรีทั้ง 7 หมวด ลิงก์เก่า และการล็อกอิน สำรองฐานข้อมูลและไฟล์ใน Storage แยกกัน
